# Картинки: патч data.win (РАБОТАЕТ)

Ставит переведённые **картинки** (спрайты), патча `data.win` на машине
пользователя. `data.win` сам не раздаётся — везём только `img/`. Проверено в игре.

## Как запускается
Обычно **через установщик**: `install.bat` / `install.sh` после текста спрашивают,
применять ли картинки, и вызывают патч сами. Напрямую:
```
# Windows
powershell -ExecutionPolicy Bypass -File patch_images.ps1
# Linux / macOS / Steam Deck (Desktop Mode)
bash patch_images.sh
```
UndertaleModCli (**nightly**) скачивается автоматически в `images/.utmt_nightly/`
(в git не коммитится, .NET не нужен). Перед патчем делается бэкап
`data.win.orig_backup`.

## Метод (почему именно так)
Выяснено опытным путём на живой игре:
- Текстуры WOH в формате **QOI**. Перекодирование страницы атласа портит её для
  рантайма игры **избирательно**: страницы со **шрифтами** при QOI-перекоде дают
  битый текст, а при PNG — битую графику. → трогать страницы шрифтов нельзя.
- Поэтому `woh_patch.csx`:
  - заменяет спрайты **на месте**, формат страницы оставляет **QOI** (графика цела);
  - **пропускает** страницы атласа, которые делят место со шрифтами
    (chfont/font_gui и др.) — глифы остаются целыми;
  - **шрифты не трогает** (стоковые нормально рисуют кириллицу).
- Нужна **nightly**-сборка UndertaleModCli: QOI-кодер релиза 0.9.2.0 ненадёжен.

## Известное ограничение
4 спрайта лежат на страницах, общих со шрифтами, поэтому **остаются английскими**:
`scard_finalcombat_13`, `scard_finalcombat_14`, `s_graphicscustom_0`, `s_newgod_1`.
Чтобы перевести и их, пришлось бы вынести шрифт на отдельную страницу — отдельная
задача.

## Откат
```
cp data.win.orig_backup data.win     # (Windows: Copy-Item)
```
или в Steam: Проверить целостность файлов. Обновление игры тоже откатывает патч —
прогнать заново.

## Steam Deck
Нативной Linux-версии нет; игра идёт через Proton, но `data.win`
платформонезависим. Патч тяжёлый (data.win ~314 МБ) и небыстрый; запускать из
Desktop Mode. После обновления игры — прогнать заново.
